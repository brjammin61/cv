# 🔐 Kalshi API Authentication Setup

## 🚨 CRITICAL: Why We Were Getting 403 Errors

Kalshi doesn't use simple Bearer token authentication. They require **RSA signature-based authentication** where each API request must be signed with your private key.

### Wrong Authentication (What We Had):
```python
headers = {
    'Authorization': 'Bearer e31300f6-6e71-4572-8068-89d7844b66e2'  # ❌ WRONG
}
```

### Correct Authentication (What Kalshi Requires):
```python
headers = {
    'KALSHI-ACCESS-KEY': 'e31300f6-6e71-4572-8068-89d7844b66e2',  # ✅ API Key
    'KALSHI-ACCESS-SIGNATURE': '<rsa_signature>',  # ✅ RSA signature of request
    'KALSHI-ACCESS-TIMESTAMP': '1731891234567'  # ✅ Timestamp in ms
}
```

**Each request requires a unique signature** generated by signing:
- The timestamp + HTTP method + path
- Using your RSA private key
- With PSS padding and SHA-256

## 🔑 How to Get Your RSA Private Key

### Step 1: Log into Kalshi

Go to: https://kalshi.com/

### Step 2: Navigate to API Settings

1. Click your profile icon (top right)
2. Go to **Settings**
3. Select **API** or **Developer Settings**

### Step 3: Generate or Download Private Key

You should see a section for API credentials. Look for:

- **"Download Private Key"** button
- Or **"Generate New Key Pair"**

When you generate a new API key, Kalshi will offer to download the private key as a `.pem` file.

**IMPORTANT:**
- The private key can only be downloaded ONCE when generated
- If you lost it, you need to generate a new API key + private key pair
- Keep this file secure - anyone with it can trade on your behalf

### Step 4: Save the Private Key

Download the file (usually named `kalshi_private_key.pem` or similar) and save it somewhere secure on your Mac.

**Recommended location:**
```bash
mkdir -p ~/.kalshi
mv ~/Downloads/kalshi_private_key.pem ~/.kalshi/private_key.pem
chmod 600 ~/.kalshi/private_key.pem  # Make it readable only by you
```

## ⚙️ Configure Oracle to Use Your Private Key

### Option 1: Update config/api_keys.py (Recommended)

Edit `oracle_system/config/api_keys.py`:

```python
KALSHI_API_KEY = "e31300f6-6e71-4572-8068-89d7844b66e2"

# Point to your private key file
KALSHI_PRIVATE_KEY_PATH = "/Users/yourname/.kalshi/private_key.pem"  # ✅ Change this path

KALSHI_API_BASE = "https://api.elections.kalshi.com/trade-api/v2"
```

### Option 2: Pass Path Directly

When initializing the connector (if you're using it programmatically):

```python
from connectors import KalshiConnector

connector = KalshiConnector(
    api_key="e31300f6-6e71-4572-8068-89d7844b66e2",
    private_key_path="/Users/yourname/.kalshi/private_key.pem",
    simulate_data=False
)
```

## 🐛 Troubleshooting

### Error: "Failed to load private key"

**Check 1:** File exists at the path you specified
```bash
ls -la /Users/yourname/.kalshi/private_key.pem
```

**Check 2:** File has correct permissions
```bash
chmod 600 /Users/yourname/.kalshi/private_key.pem
```

**Check 3:** File is in PEM format
```bash
head -1 /Users/yourname/.kalshi/private_key.pem
# Should show: -----BEGIN PRIVATE KEY----- or -----BEGIN RSA PRIVATE KEY-----
```

### Error: "Authentication failed" or 403

**Possible causes:**
1. Wrong API key (doesn't match the private key)
2. Private key is for a different API key
3. Need to regenerate both API key AND private key together
4. Account doesn't have API access enabled

**Solution:** Generate a fresh API key + private key pair from Kalshi website.

### Error: "ModuleNotFoundError: No module named 'cryptography'"

Install the cryptography library:
```bash
pip3 install cryptography
```

Or reinstall all requirements:
```bash
pip3 install -r requirements.txt
```
